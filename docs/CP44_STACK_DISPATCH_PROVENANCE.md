# CP44 — Scheduler dispatch-level provenance for the invalid EE return

CP41 authentic native boot established: the main EE guest thread executes original translated epilogue at 0x002BE014, restores $ra from the guest stack, and jumps to invalid, unaligned 0x00000F82. The previous low-level original guest trace and scheduler diagnostics independently agree that this is a control-flow problem, not a missing translated function. Original game GS display is not verified.

CP43 added an opt-in original guest `WRITE8/16/32/64/128` memory watch for the measured saved-return-address slot at physical 0x01FFFF10. Changing the common generated-code header causes a large AOT recompilation, so CP44 adds the complementary memory *snapshot* tracing entirely inside the native EE scheduler implementation (.cpp). It reads the same eight bytes before/after each native guest dispatch. If they change, it logs `[EE:stack-dispatch-delta]` containing original dispatched PC, next PC, SP, RA and old/new bytes. This catches changes even if the underlying write bypasses the AOT macro instrumentation, without fabricating guest state or using game-specific execution branches. The feature is enabled only when the existing `PS2X_GUEST_WATCH_ADDR` debug environment variable is set and logs are capped. Runtime behavior remains unchanged.

The native original-ISO first-frame workflow now preserves first observed guest writes and dispatch deltas in `built/reports/link_ci_frame.txt`, rather than only reporting final guest ticks. Next action: inspect the measured last write that introduced 0xF82; repair the general memory/ABI/control-flow bug only once established. Generated console assets and original guest binary are never altered.
